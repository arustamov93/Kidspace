# Compliance, Data Privacy & Healthcare Policy (KidSpace 5.0)

Этот документ регламентирует обработку чувствительных данных (PII, PHI), политику телемедицины и аудита безопасности в соответствии с локальным законодательством (Закон РУз "О персональных данных") и международными стандартами (HIPAA/GDPR - как best practices).

---

## 1. Политика хранения медицинских данных (PHI)

Мы разделяем данные на PII (Personally Identifiable Information — ФИО, телефон) и PHI (Protected Health Information — диагнозы, переписка с врачом).

### Архитектура хранения
1.  **Encryption at Rest:**
    *   Все данные в Firestore и Cloud Storage шифруются автоматически (Google-managed keys).
    *   Особо чувствительные поля (например, `medical_report` в коллекции `consultations`) подвергаются дополнительному шифрованию на уровне приложения (Application-Level Encryption) перед записью в БД. Ключи дешифровки доступны только участникам консультации.
2.  **Encryption in Transit:**
    *   Все соединения используют TLS 1.2+ (HTTPS/WSS).
3.  **Isolation:**
    *   Медицинские документы (справки, анализы) хранятся в отдельном закрытом бакете Cloud Storage (`gs://kidspace-medical-records`), доступ к которому возможен только через Signed URLs с коротким сроком жизни (15 минут).

## 2. Согласие пользователя на телемедицину (Informed Consent)

Перед получением первой медицинской услуги (чат или видео) пользователь **обязан** подписать информированное согласие.

### Юридический текст (Draft)
> "Я даю согласие на получение медицинских консультаций в дистанционном формате (телемедицина). Я понимаю, что онлайн-консультация не заменяет очный осмотр и не может использоваться в экстренных случаях. Я разрешаю обработку моих данных и данных моего ребенка для целей диагностики."

### Процесс подписания (Digital Signature)
1.  Пользователь нажимает "Записаться к врачу".
2.  Система проверяет флаг `has_signed_consent` в профиле пользователя.
3.  Если `false`, открывается **Consent Screen**.
4.  После нажатия "Принимаю", в коллекцию `consents` записывается документ:
    *   `user_id`: UID пользователя.
    *   `timestamp`: Время сервера.
    *   `ip_address`: IP адрес устройства.
    *   `version`: Версия соглашения (v1.0).
    *   `user_agent`: Модель устройства.

## 3. UI: Consent Screen (Экран согласия)

Этот экран должен быть блокирующим (нельзя закрыть без решения).

**Элементы интерфейса:**
1.  **Заголовок:** "Важная информация".
2.  **Body Text:** Скроллируемая область с полным текстом соглашения.
3.  **Checkbox 1 (Required):** "Я подтверждаю, что являюсь законным представителем ребенка".
4.  **Checkbox 2 (Required):** "Я ознакомился с правилами телемедицины и даю согласие на обработку данных".
5.  **Action Buttons:**
    *   "Отказаться" -> Возврат на главный экран.
    *   "Подписать и продолжить" (Активна только при всех галочках).

## 4. Журнал аудита (Audit Logs)

Любое действие с медицинскими данными должно быть залогировано. Это требование безопасности ("Кто смотрел медкарту ребенка?").

### Коллекция `access_logs` (Только Write, Read для Security Officer)
| Поле | Описание |
| :--- | :--- |
| `actor_id` | UID того, кто совершил действие (Врач/Админ). |
| `target_id` | UID пациента/ребенка, чьи данные просмотрены. |
| `resource` | Ссылка на документ (`consultations/123`, `storage/file.pdf`). |
| `action` | 'READ', 'WRITE', 'EXPORT'. |
| `timestamp` | Server Timestamp. |
| `reason` | 'Scheduled Consultation', 'Support Request'. |

**Правило:** Врачи имеют доступ к данным пациента *только* в период активной консультации и 24 часа после неё. Любой доступ вне этого окна помечается флагом `suspicious` в админке.

## 5. Политика удержания данных (Retention Policy)

Как долго мы храним данные.

1.  **Медицинские записи (Consultation Notes):**
    *   Хранятся **5 лет** с момента последнего обращения (стандарт для амбулаторных карт).
    *   После удаления аккаунта пользователем, медицинские данные не удаляются физически, а архивируются в "Cold Storage" для соблюдения законодательства.
2.  **Чаты и Медиа:**
    *   Хранятся **1 год**. Далее текст анонимизируется, медиафайлы удаляются.
3.  **Платежные данные:**
    *   Хранятся **3 года** (налоговая отчетность).
4.  **Временные файлы:**
    *   Видеозвонки **не записываются** (P2P stream). Если запись необходима по закону, она шифруется и хранится 30 дней.

## 6. Обработка чувствительных данных (Sensitive Data Handling)

### Маскирование (Masking)
В логах сервера, админ-панели и уведомлениях данные должны быть маскированы:
*   Телефон: `+998 90 *** ** 12`
*   Имя ребенка: `Ali **.`
*   Паспортные данные: Скрыты полностью.

### Права доступа (Access Control)
*   **Разработчики:** Не имеют доступа к продакшн-данным PHI. Для тестов используются mock-данные.
*   **Служба поддержки:** Видит только факт наличия консультации (ID, Дата, Врач), но **не видит** переписку, диагнозы и фото.
*   **Врачи:** Видят полную историю только тех пациентов, с которыми у них есть активная связь.

## 7. Процедура удаления данных (Right to be Forgotten)

Если пользователь запрашивает удаление аккаунта:
1.  **Soft Delete:** Флаг `is_deleted=true`. Данные скрываются из UI.
2.  **Grace Period (30 дней):** Возможность восстановления.
3.  **Hard Delete:**
    *   Удаление PII из коллекции `users` (замена имени на "Deleted User").
    *   Удаление фото профиля.
    *   Медицинские записи (PHI) переносятся в закрытый архив (Legal Hold) и удаляются из оперативной БД.

---

## 8. Аварийный план (Data Breach Protocol)

В случае утечки данных:
1.  **Detection:** Алерт от системы мониторинга (необычный объем чтений БД).
2.  **Containment:** Блокировка всех API ключей и токенов.
3.  **Notification:** Уведомление пользователей в течение 72 часов (Push + Email + SMS).
4.  **Report:** Отчет регулятору (Узкомназорат/Минздрав) с описанием инцидента и принятых мер.
